# 文件夹图片读取 - DDHT

分类：`DDHT/Image`；节点类型：`DDHT_FolderImage`。

每次节点执行从文件夹读取一张图片，输出给下游，并在节点内显示预览。更新仓库后重启 ComfyUI，即可搜索节点名称添加；常见格式无需新增依赖。

## 输入

| 参数 | 默认值 | 作用 |
| --- | --- | --- |
| 文件夹路径 | 空 | 填写运行 ComfyUI 的机器上的图片目录，支持中文、空格、带引号路径和环境变量；建议使用绝对路径 |
| 读取方式 | 洗牌袋 | 独立均匀随机、洗牌袋、时间间隔加权随机或顺序；旧名称“随机”等同洗牌袋 |
| seed | 0 | 决定随机结果；三种模式的种子规则见下文，顺序模式忽略它 |
| 包含子文件夹 | 关闭 | 开启时扫描下级目录，不跟随目录符号链接 |
| 顺序起始索引 | 0 | 顺序模式第一次读取的位置，从 0 计数；超出图片数时取余 |
| 顺序重置标记 | 0 | 改成另一个整数后，下一次从起始索引重新开始 |
| 填充透明区域 | 关闭 | 开启时将透明区域和半透明边缘与指定颜色合成 |
| 填充颜色 | #FFFFFF | 支持 `#RRGGBB` 或 `#RGB`；白色 `#FFFFFF`、黑色 `#000000`、绿色 `#00FF00` |
| 随机重置标记 | 0 | 改成另一个整数后，下一次洗牌袋读取会重建列表，加权读取会清零并重建权重文档；均匀随机忽略它 |

在其他电脑的浏览器中操作 ComfyUI 时，应填写 ComfyUI 服务器能读取的目录。不会上传文件，也不会修改源图片。

## 三种随机方式

| 方式 | 选取规则 | 是否可能重复 | 状态保存 |
| --- | --- | --- | --- |
| 独立均匀随机 | 每次从全部图片中等概率抽取，不参考历史 | 可能连续重复 | 无历史 |
| 洗牌袋（默认） | 打乱全部图片，依次取完，再打乱下一轮 | 一轮内不重复；至少两张图时跨轮也不连续重复 | 当前节点实例内存 |
| 时间间隔加权随机 | 距上次使用的成功抽取次数越多，权重越大 | 允许重复，不保证一轮全部覆盖 | 每个文件夹一份持久化 JSON |

三种模式都使用独立随机数生成器，不影响采样器或其他节点的随机状态。去重和历史记录依据文件路径；同一内容保存为两个不同文件时，仍被视为两张图片。

### 独立均匀随机

每次只根据当时的 `seed` 从当前文件列表抽取一张，每张图片的概率为 `1 / 图片总数`。**固定种子且文件列表不变时会选中同一张**；需要每次重新抽取时，将种子旁的 `control_after_generate` 设为 `randomize`。即使种子每次变化，独立抽取也允许再次选中相同图片。

此模式不创建或更新权重文档，也不保留播放列表。

### 洗牌袋

先将全部图片索引洗牌，再逐张输出：

1. 首次执行时，用种子打乱完整图片列表。
2. 每次执行读取列表中的下一张，一轮内每个文件恰好输出一次。
3. 全部输出后重新洗牌，开始下一轮；图片数至少为 2 时，新一轮首张不会是上一轮末张。
4. 只有一张图片时，每次输出该图片。

**固定 seed 也会逐张前进**；同一文件列表、相同种子配置从头开始，可以复现完整播放序列，轮次也参与洗牌。种子旁的 `control_after_generate` 控件可用 `fixed` 保持种子，或用 `randomize` 更新种子：只在生成下一轮列表时读取当时的种子，自动更新种子不会打断当前轮。手动改变 seed 想立即生效时，同时改变“随机重置标记”。

列表一旦生成，读取、张量转换、预览失败或中断都不消费当前图片；即使失败后 seed 被自动更新，也会先重试当前项。成功输出后，后续节点失败不会回退播放进度。不同节点实例各自保存列表。

更换目录、改变扫描范围、文件列表增删改名、改变随机重置标记，或成功执行其他读取模式后切回洗牌袋，会从第 0 轮重建列表；重建后可能重新遇到旧列表已播放的图片。修改透明填色设置、顺序起始索引或顺序重置标记不会打断随机列表。仅替换同名文件的内容时保留播放进度。

### 时间间隔加权随机

这里的“时间间隔”按**该文件夹在加权模式下成功输出了多少张图片**计算，不按现实经过的秒数计算：暂停一天不会改变权重。

初始每张图片权重都是 1。每次成功输出后更新全部图片权重并重新排序：

```text
权重 = 累计成功抽取次数 - 该图片上次使用的抽取序号 + 1
被选概率 = 该图片权重 / 所有图片权重之和
```

从未使用过的图片，其上次使用序号按 0 计算。刚输出的图片权重回到 1，其余图片权重随抽取次数增加。例如三张图初始权重为 `A=1, B=1, C=1`，输出 A 后变成 `A=1, B=2, C=2`，下一次 A 的概率为 20%，B、C 各为 40%。这是按权重抽取，不是永远选排名第一的图片。

种子与文档中的累计抽取次数共同决定结果，因此固定 seed 也会继续推进。同样的图片列表、初始文档和种子变化序列可以复现相同结果；只修改 seed 不清空历史。

#### 每个文件夹的权重文档

首次执行加权模式时自动创建 UTF-8 JSON。默认位置为：

```text
ComfyUI/user/ddht/folder_image_weights/<文件夹路径的哈希>.json
```

如果 ComfyUI 自定义了用户目录，则使用实际用户目录。节点新增的“权重文档”输出会返回这份文件的完整路径；其他模式返回空字符串。图片源文件夹中不写入状态文件。

文档包含文件夹路径、创建/更新时间、文档代次、重建原因、累计抽取次数，以及每张图片的相对路径、内容 SHA-256、文件大小、权重、排名、使用次数和上次使用时间。图片条目按权重从高到低排列；同权重按路径排列，排名不改变抽取概率。

- 同一个文件夹共用一份当前文档；不同文件夹各有文档。重启 ComfyUI、重新创建节点后可以继续历史。
- 多个节点或本机进程使用同一文件夹时，通过文档锁协调更新。它们共享历史，不各自建立一套权重。锁文件 `.json.lock` 是正常的辅助文件。
- 每次加权执行都扫描图片列表并读取全部候选文件的内容指纹。图片**新增、删除、改名或内容变化**时，将旧文档替换为全新的一代，清空历史、重新赋予初始权重；同名、同大小且保留修改时间的内容替换也能识别。
- 重建沿用该文件夹的 JSON 路径，不堆积历史文档。非图片文件变化、图片仅修改时间而字节不变，不会清空历史。
- 修改“包含子文件夹”或“随机重置标记”也会重建。多个节点共用目录时，这两个设置应一致，否则会相互触发重建。
- 切换到其他模式不会删除文档，其他模式的读取也不会计入加权历史。切回时检查图片列表和内容，再继续或重建。
- 空目录会重建为空文档并报错；文档损坏时重新建立。读取、预览失败或取消不会增加使用次数。JSON 保存失败会报错，不返回本次图片结果。

成功计数发生在本节点完成图片读取、预览和文档保存时；下游节点之后失败不会回退使用记录。文档采用临时文件加原子替换保存，避免正常写入过程中留下半份 JSON。ComfyUI 用户目录需要可写。

**完整内容指纹会增加磁盘读取开销**，大文件夹比另外两种模式慢；不会将全部图片解码或一次性载入内存。

## 顺序与兼容性

**顺序模式**按相对文件名自然排序，不区分英文大小写；例如 `1.png → 2.png → 10.png → 1.png`。每次节点成功读取并生成预览后前进一张；读取或预览失败不前进。不同节点实例各自计数，后续节点失败不会回退本节点已经完成的读取。

顺序模式更换目录、修改起始索引/顺序重置标记、切换扫描范围、文件列表增删改名，或成功执行随机读取后切回顺序时，从起始索引重新开始。

洗牌袋列表和顺序进度均保存在当前 ComfyUI 节点实例中。重启 ComfyUI、重建节点或清除节点对象缓存会重置它们；禁用对象缓存的运行方式不保留它们的进度。加权模式的文档不受这些内存重置影响。播放列表仅保存文件索引，不会预先将整个文件夹的图片载入内存。

旧工作流的“随机”选项保留为“洗牌袋”的兼容名称，原控件顺序和前六个输出连接保持兼容。新节点默认选择“洗牌袋”；“随机重置标记”仍位于控件末尾且默认为 0。

每次执行都会重新扫描目录并读取文件，避免复用上一次图片缓存；替换同名文件后也会读取新内容。目录为空、路径错误、所选图片损坏或缺少解码器时会明确报错，不会悄悄换成其他图片。

## 格式与透明区域

支持 JPG/JPEG/JFIF、PNG/APNG、WebP、BMP/DIB、GIF、TIFF、ICO、TGA、PPM/PGM/PBM/PNM、PCX、DDS 和 JPEG 2000 等 Pillow 可解码的格式。扩展名不区分大小写。AVIF 需要当前 Pillow 带 AVIF 支持，旧环境可安装 `pillow-avif-plugin`；HEIC/HEIF 需要在 ComfyUI 的 Python 环境安装 `pillow-heif`。不同环境的编译选项可能影响部分格式，详见 [Pillow 格式文档](https://pillow.readthedocs.io/en/stable/handbook/image-file-formats.html)。

GIF、动态 WebP/APNG、多页 TIFF 等每次只取第一帧/第一页。应用 EXIF 方向，支持调色板透明、灰度透明和 CMYK 转 RGB；16 位灰度 PNG/TIFF 会归一化到 0～1，避免中间灰度变成纯白。

- **关闭填充**：`IMAGE` 输出 RGB，透明信息单独输出为 `MASK`，与 ComfyUI 的常用约定一致：完全透明为 1，完全不透明为 0。下游需要同时使用遮罩才能保留透明效果；仅连接 IMAGE 不会自动传递 Alpha。
- **开启填充**：按 Alpha 与填充颜色合成 RGB，半透明边缘也会混合；输出遮罩为全 0。该选项也适用于 WebP 等带透明度的格式。

## 输出与预览

| 输出 | 内容 |
| --- | --- |
| 图片 | 一张原尺寸 RGB 图片，`IMAGE [1,H,W,3]`，float32、0～1 |
| 透明遮罩 | `MASK [1,H,W]`，填色后或无透明区域时全 0 |
| 文件名 | 所选图片的文件名，包含扩展名 |
| 完整路径 | 所选图片的绝对路径 |
| 图片索引 | 在当前文件名自然排序列表中的位置，从 0 开始；不是随机播放列表中的播放进度 |
| 图片总数 | 当前目录及选定扫描范围内的图片候选数 |
| 权重文档 | 加权模式的 JSON 完整路径；其他模式为空字符串 |

预览使用 ComfyUI 自带的图片显示功能，无需单独连接预览节点，也能单独执行本节点。临时目录中生成最长边不超过 1024 的 PNG 缩略图；下游图片保持原尺寸。预览反映当前填色效果，关闭填色时保留 Alpha。源图和永久输出目录均不写入副本，临时预览由 ComfyUI 临时目录管理。

典型连接：`文件夹图片读取 → 局域网 LLM / DeepSeek API / 图片处理节点`。
