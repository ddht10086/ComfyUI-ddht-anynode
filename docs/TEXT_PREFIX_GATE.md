# 文本开头校验 - DDHT

分类：`DDHT/Text`。节点类型：`DDHT_TextPrefixGate`。

用于检查本地 LLM 输出是否符合预定的开头格式。匹配时原样输出文本；不匹配时抛出明确错误，由 ComfyUI 终止本次工作流执行。

## 输入与输出

| 输入 | 用途 |
| --- | --- |
| `text` | 连接 LLM 输出的文本（STRING） |
| `expected_prefix` | 要求出现的开头字符，可包含多行，不能为空 |
| `ignore_leading_whitespace` | 默认关闭；开启后仅在检查时跳过输入文本开头的空格、换行、制表符等空白 |

输出 `text` 与输入完全相同：不删除前缀、不删除空白、不截断文本。

## 使用示例

要求 LLM 的正确输出以 `视频提示词：` 开头，把 `expected_prefix` 填为 `视频提示词：`：

| LLM 输出 | 严格匹配 | 忽略开头空白 |
| --- | --- | --- |
| `视频提示词：人物站在房间里……` | 通过 | 通过 |
| ` 视频提示词：人物站在房间里……` | 失败 | 通过 |
| `下面是视频提示词：……` | 失败 | 失败 |
| `视频提示词:……`（半角冒号） | 失败 | 失败 |
| 空文本 | 失败 | 失败 |

连接顺序：LLM 的文本输出 → 本节点的 `text` → 文本长度门控（可选）→ 文本编码／后续节点。

必须让需要保护的后续节点使用本节点的输出。仅在画布上放置本节点，或让其他节点直接读取原始 LLM 输出，不能保证这些节点先等待校验。不要把校验节点设为旁路。

## 匹配细节

- 比较的是前 N 个 Unicode 字符，N 为 `expected_prefix` 的长度；不是字节数，也不是 token 数。
- 只做开头匹配，不是全文相等，也不是在正文中搜索。
- 区分大小写、标点、全半角；不执行正则表达式，不做 Unicode 归一化。
- 多行前缀请直接输入实际换行，字面字符 `\n` 不会自动变成换行。
- 忽略空白使用 Python 的 `str.lstrip()`；不移除 `<think>`、Markdown 代码围栏、BOM 或零宽空格。不修改 `expected_prefix` 本身。
- 空前缀会被拒绝，避免无意中让所有输出通过；静态填写的空前缀会在工作流开始前报错。
- 失败通过普通节点异常终止当前任务，不清空其他排队任务，不设置全局中断标志，也不撤销已完成的计算或已保存的文件。已经启动的独立异步操作不保证被取消。
- 相同输入可以使用 ComfyUI 缓存；文本、前缀或选项变化后会重新检查。

本节点只验证开头格式。即使前缀正确，也不能保证后面的内容在语义上正确。

## 安装与验证

在已安装的本项目目录执行 `git pull`，重启 ComfyUI，在 `DDHT/Text` 中搜索“文本开头校验”。无需新增依赖。

专项测试：`python -m unittest discover -s tests -p test_text_prefix_gate.py -v`。
